# Rendyn keyword research — 29 September 2026

Prioritize the existing Cursor and Claude Code template articles, a small set of specific React component pages, and a new landing page for AI agent UI components. These connect early search visibility to what Rendyn actually provides. Broad terms such as “React components” are useful positioning language but are a weaker first growth target.

This research combines authenticated Google Search Console data, current public search results and competitor pages, Rendyn’s live website, and its local catalogue and guide registry. The working audience is English-speaking developers and founders worldwide. The country sample includes 231 impressions from the US, 66 from India and 59 from the UK; it does not support restricting the strategy to the UK.

## Competition and positioning

- [shadcn’s MCP server](https://ui.shadcn.com/docs/mcp) already supports finding and installing registry components. [Magic UI](https://magicui.design/docs/mcp) also publishes its own MCP integration. “We have MCP” is therefore insufficient differentiation.
- [21st’s MCP guide](https://docs.21st.dev/blog/mcp-ui-components) describes catalogue discovery, previews and installation. Rendyn needs to demonstrate why its curation, choice process or implementation guidance saves the user effort; similar feature labels alone do not establish an advantage.
- [assistant-ui](https://www.assistant-ui.com/) and its [tool UI documentation](https://www.assistant-ui.com/docs/tools/tool-ui) cover agent interfaces and runtime-connected tool states. Rendyn should precisely describe its reusable UI source and avoid implying that a visual component supplies an entire agent backend.
- [Superdesign’s Claude Code design article](https://superdesign.dev/blog/claude-code-ui-design) directly addresses poor AI-generated interface design. Original before/after builds would help Rendyn’s existing guides contribute more than another general prompting checklist.
- [Magic UI’s progressive blur](https://magicui.design/docs/components/progressive-blur), [orbiting circles](https://magicui.design/docs/components/orbiting-circles) and [Kibo’s Kanban](https://www.kibo-ui.com/components/kanban) are also upstream alternatives. Rendyn imports these sources: add original usage explanations, comparisons and integration examples while preserving attribution. Repeating upstream descriptions gives readers little additional reason to choose Rendyn.

The defensible positioning to test is: **find an appropriate React component, inspect its behavior, and give your coding agent the source and setup context needed to adapt it.** Treat claims about superior speed, reliability or quality as hypotheses until demonstrated.

## Content and site gaps

1. **The agent collection has no dedicated indexable landing page.** Live browser inspection confirmed `/components?category=agents` displays 17 matches but uses `noindex, follow` and canonicalizes to `/components`. Keep filtered search URLs controlled. Create an editorial collection page with its own URL, introduction, use-case groupings and links to the components; do not simply make every filter indexable.
2. **The Claude template article mixes several intents.** Its live heading covers skills, agents and websites, and the local content mostly discusses instructions, skills and tooling. Website-specific queries deserve an actual website starter comparison, examples and a clear distinction between complete templates and Rendyn’s component catalogue. A title change alone will not fix the mismatch.
3. **Many broad design guides already exist.** The guide registry contains 12 articles. Upgrade the existing Claude, Cursor and vibe-coding pages before creating more near-duplicate guides for synonymous searches. Proposed integration content should answer setup/use questions, not repeat a design essay.
4. **Component titles offer a reusable improvement opportunity.** Current metadata follows `[Name] React Component`. For selected pages, make titles and descriptions explain the specific job where that improves clarity. Preserve established URLs, including the variant URLs, and give variants distinct intent rather than making them compete for identical descriptions.

## What to do first

Suggested allocation: roughly 60% improving existing pages, 25% building the agent collection and supporting examples, 15% developing the MCP product page. This is a planning recommendation, not a measured optimal split.

1. **Improve the two template articles.** Start with the pages already receiving 68 and 55 impressions. Keep their URLs. A possible Cursor title is “Cursor Website Templates: 7 Useful Starting Points”; the Claude article should earn a website-focused title only after adding substantial matching content. Include screenshots, framework/use-case comparisons, accurate access terms and links into relevant Rendyn components.
2. **Enrich progressive blur, orbiting circles and dropzone.** Use original examples, concise integration guidance and accurate component limits. These have relevant disclosed queries close to the first page, but the samples remain too small to promise gains.
3. **Publish the agent UI collection.** Connect approval, tool permission, image generation, streaming and composer components into a coherent workflow. Start with one strong page rather than many thin keyword landing pages.
4. **Strengthen the existing Claude design guide and build `/mcp`.** Use a real workflow demonstration and explain how the product fits into the reader’s current tools. Verify client instructions when authoring them.
5. **Reassess after 28 complete days, then again over a longer window.** Compare page/query groups using equal periods, country/device mix and disclosed-query limitations. Track qualified visits, catalogue engagement and successful MCP use or trial activation where consented analytics support it. At this traffic level, do not treat a few clicks as a statistically reliable CTR or conversion result.

Do not prioritize `react floor planner` (31 impressions), `react venn diagram` (30), or `react decision tree` (9) just because they top the query report. The current catalogue has no corresponding named components, and average positions are 77.9, 72.5 and 54.6. Similarly, competitor-brand searches such as `leafygreen ui` and `evergreen react ui` do not automatically represent suitable acquisition targets.
